<objective>
## Goal
Replace the three stub analysis nodes (classify, ground, tribunal) with LLM-powered implementations using Gemini Flash via LangChain, producing real diagnosis from the canned trace.

## Purpose
Phase 1 proved the graph skeleton works. Phase 2 makes it intelligent. After this phase, the pipeline produces a real diagnosis from trace data, not hardcoded stubs. This is the core value of the demo.

## Output
- `rescue/nodes/classify.py`: LLM classifies failures with structured output
- `rescue/nodes/ground.py`: Tools read repo files, LLM maps failures to code
- `rescue/nodes/tribunal.py`: Two-agent pattern (proposer + challenger) produces validated diagnosis
- `rescue/tools.py`: File-reading tools for the grounding engine
- Pipeline produces real, LLM-generated analysis when run
</objective>

  <name>Task 3: Implement tribunal diagnoser with two-agent pattern</name>
  <files>rescue/nodes/tribunal.py</files>
  <action>
    Replace stub with two-agent tribunal pattern:

    1. Load dotenv, init ChatGoogleGenerativeAI(model="gemini-2.0-flash", temperature=0)

    2. Agent 1 (Proposer):
       - System prompt: "You are a senior incident analyst. Given classified failures and source code evidence, propose a root cause diagnosis with remediation steps."
       - Input: classifications, grounding evidence from messages, incident brief
       - Output: proposed Diagnosis (root_cause, confirmed_failures, remediation_steps)

    3. Agent 2 (Challenger):
       - System prompt: "You are a skeptical reviewer. Challenge the proposed diagnosis. Reject any conclusions not supported by direct evidence from the trace or source code. Identify dismissed hypotheses."
       - Input: the proposer's diagnosis + original evidence
       - Output: final Diagnosis with dismissed_hypotheses populated

    4. Use structured output for both agents: llm.with_structured_output(Diagnosis)
    5. Print diagnosis summary (confidence, root cause preview, remediation count, dismissed count)

    The two calls happen sequentially within the single tribunal_node function.
    This is NOT a graph-level multi-agent pattern. It's two LLM calls within one node.

    Avoid: Making this a separate sub-graph (overkill for the demo)
    Avoid: Skipping the challenger (the whole point is the two-agent validation)
  </action>

from dotenv import load_dotenv; load_dotenv()
from rescue.nodes.tribunal import tribunal_node
from rescue.schemas import RescueState, TraceEvent, FailureClassification
from langchain_core.messages import HumanMessage
import json
events = [TraceEvent(**e) for e in json.load(open('data/traces/research-agent-failure.json'))]
classifications = [
    FailureClassification(failure_type='approval_bypass', confidence=0.95, evidence=['router skipped approval'], affected_nodes=['router']),
    FailureClassification(failure_type='swallowed_error', confidence=0.9, evidence=['web_search error ignored'], affected_nodes=['verify_claims']),
]
state = {

    'repo_path': 'data/repo', 'classifications': classifications,
    'diagnosis': None, 'eval_cases': [], 'debrief': None,
    'messages': [HumanMessage(content='Repo grounding: route_after_verify() in graph.py only checks claims_verified, missing approval_required check. web_search in tools.py has no retry or error propagation.')]
}
result = tribunal_node(state)
d = result['diagnosis']
assert d is not None, 'No diagnosis produced'
assert len(d.dismissed_hypotheses) >= 1, 'No dismissed hypotheses'
assert len(d.remediation_steps) >= 1, 'No remediation steps'
print(f'PASS: diagnosis confidence={d.confidence:.0%}, {len(d.remediation_steps)} remediation steps, {len(d.dismissed_hypotheses)} dismissed')
